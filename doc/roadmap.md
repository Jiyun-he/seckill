# 路线图

[← 返回 README](../README.md)

当前实现的边界是：**秒杀链路的正确性与容量已闭环，但订单生命周期尚未闭环，限流与高可用仍是单点。**

以下为后续方向，按主题分组，不承诺时间。

## 业务闭环

订单目前止步于「落库」，`order.status` 恒为 0（未支付）。

- 订单支付、取消与超时关闭流程
- 延迟队列处理超时未支付订单，释放库存
- 管理员接口：维护商品与秒杀活动（当前活动配置只能改数据库，且开始后禁止修改）
- 前端页面，形成完整可演示的业务闭环

## 容量与防护

接口层已通过 Redis 预占 + MQ 削峰把同步路径压到很薄，但目前**没有限流**：库存耗尽后的请求仍会走到 Redis，被 Lua 拒绝而非在入口拦截。

- 秒杀接口限流与用户级频控，库存接近耗尽时快速失败
- 消费者批量落库（合并 INSERT）或分库分表，突破 DB 连接池这一层瓶颈
- 热点活动预热策略的进一步优化

## 可用性与可观测性

Redis、RabbitMQ、MySQL 目前均为单实例，任何一处故障都会中断链路。

- Sentinel 或 Redis Cluster 提升缓存高可用能力
- RabbitMQ 集群与镜像队列
- Prometheus + Grafana 可观测性建设：MQ 积压、落库 TPS、DB 等待连接等关键指标可视化与告警（当前仅暴露 Actuator 的 `health` 与 `metrics`）
- 链路追踪（OpenTelemetry / Micrometer Tracing）
